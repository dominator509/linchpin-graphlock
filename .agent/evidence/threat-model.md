- Product: LINCHPIN -- local-first Windows patent-intelligence and commercialization desktop application
- Deployment: single-user device-local install (MSI/NSIS); no server, no fleet, no shared state
- Reviewed: round 54, epoch 05bfbdbb314d13ca
- Method: asset/boundary enumeration from the code (SCOPE_MAP, TRUTH_BOUNDARIES, the command registry and the gate ladder), then STRIDE per asset, with each mitigation bound to a symbol and an executed check

## Assets

| ID | Asset | Why it matters |
| --- | --- | --- |
| A-1 | invention content and conception records | the user's confidential disclosure; the product's reason to exist and its highest-value secret |
| A-2 | durable vault (SQLite + WAL) and blob store | holds A-1 and the audit trail; corruption or loss destroys unrecoverable work |
| A-3 | conception ledger and audit chain | provenance of who conceived what (human vs AI origin); the record a patent workflow depends on |
| A-4 | filing packages, evidence bundles and export artefacts | leave the device; an over-disclosing export is irreversible |
| A-5 | release artefacts (executable, MSI, NSIS setup) and their digests | what the user installs and runs |
| A-6 | provider prompts and completions | carry A-1 to an inference boundary if routed off-device |
| A-7 | operator diagnostics, traces and incident capsules | grow without bound and can capture secrets if redaction fails |

## Threats

| ID | STRIDE | Asset | Attack | Mitigation | Residual |
| --- | --- | --- | --- | --- | --- |
| T-01 | Spoofing | A-1 | a tool or client claims capabilities it was not granted and drives the product on the user's behalf | MCP capability grants are explicit per server/client/workspace/capability and deny by default; a request for a capability not granted is refused. | there is no user identity to spoof: the product has no login, session or role surface (measured scan: zero auth constructs), so spoofing reduces to capability grants and file access. |
| T-02 | Tampering | A-2 | an attacker or a crash corrupts the vault, or a restore silently replaces live state with an empty database | writes are reconciled by content digest, a mistyped backup path is refused instead of created, restore recreates and quarantines a missing destination, and the audit chain detects tampering. | the vault is a device-local SQLite database, not an OS-encrypted container, and the only KeyringStore is an in-process map -- stated by the product's own scope map (UO-01). |
| T-03 | Repudiation | A-3 | AI-generated content is presented as human conception, or a record is edited without trace | conception events carry an origin label that cannot be conflated, the ledger is read back through the product, and the audit chain is hash-chained with a tamper-detecting test. | the ledger read returns all events for a workspace with no pagination, and the chain is local: a user with filesystem access can delete the whole vault, which is detectable only as absence. |
| T-04 | Information disclosure | A-1 | invention content leaves the device through a provider call, a log line, a telemetry field or an export | the provider transport refuses any non-loopback endpoint with POLICY and makes no attempt; telemetry and diagnostics run through a redaction policy; the disclosure firewall refuses restricted exports; the evidence boundary hardens paths and archive entries. | redaction removes what it can attribute to a key name or a known token shape; unlabelled secret material pasted into free text is not detectable by either layer. |
| T-05 | Information disclosure | A-6 | a misconfigured endpoint sends prompts to a remote host that logs or trains on them | the local adapter builds loopback URLs only, the endpoint is validated before any I/O, an unreachable port yields a transport error rather than fabricated text, and unwired provider lanes report Unimplemented instead of silently resolving to a fake. | no credentialed provider lane exists (openai/anthropic/xai report not-wired and configured=false), so a remote lane's credential and egress behaviour is unexecuted; DOD-014 records this. |
| T-06 | Denial of service | A-2 | concurrent writers, a lock-holding backup or a failing disk makes the vault unusable or silently drops work | busy timeouts with bounded retries, a journal-mode switch only when the file is not already WAL, an online-backup retry on lock errors, a stress trial with encoded latency/throughput floors and non-vacuity assertions, and a soak trial that samples the working set. | the clause's full soak scale (24/48/72+ hours) is uncompleted: only abbreviated trials have run, and DOD-038 is DEFERRED_LONG_RUNNING. |
| T-07 | Elevation of privilege | A-1 | a crafted path or archive entry escapes the evidence directory and writes or reads outside it | path and archive-entry hardening rejects absolute paths and traversal, verified by a property test over a generated corpus and by the mutation proof that removes the guard. | the product spawns no shell and holds no elevation path; the remaining privilege surface is the user's own filesystem rights. |
| T-08 | Tampering | A-5 | a substituted or corrupted installer is shipped or installed | artifact digests are pinned in the release gate and the run manifest, the installed artifact is verified against the payload the MSI carries, the production artifact is asserted to open no debug port, and the build is reproducible. | the release is UNSIGNED (ADR-003): a digest proves integrity against an out-of-band value, not authorship, so a compromised distribution channel is not defended against. |
| T-09 | Information disclosure | A-7 | diagnostics or an incident capsule captures invention text or a credential | the diagnostics recorder redacts before storing, an induced failure is asserted to carry its correlation id with a planted credential absent from every recorded detail, and the capsule export guard refuses a surviving registered secret. | the diagnostics surface is device-local with no exporter, so there is no off-device log pipeline to harden; alerting beyond the in-app surface does not exist. |
| T-11 | Information disclosure | A-4 | an export or filing package carries restricted content, an unanchored claim or a document format the product cannot actually produce, and the disclosure cannot be recalled | the export gateway refuses restricted content, the support matrix blocks a package whose limitations are unanchored, a package never claims a document format the product does not generate, exports are confirmation-gated and audited, and the boundary guard refuses text that promises an outcome. | the product's own formats are covered (vault, evidence bundle, filing package); no third-party docketing interchange format is implemented, so a downstream system cannot help catch an over-disclosure. |
| T-10 | Tampering | A-5 | a compromised or vulnerable dependency enters the build | locked dependency graphs, advisory and ban scanning, licence policy, SBOM generation with currency enforcement, secret scanning over the tracked tree, and a clean-environment build from the committed locks. | crate checksums are verified by Cargo itself rather than independently, the SBOM covers Rust and npm components only, and two moderate dev-only npm advisories are disclosed as accepted risk. |
