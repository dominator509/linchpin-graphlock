feat(GEN-027,DOD-038): executed mutation-fuzz campaign; fixed a redactor panic it found

The registry recorded GEN-027 as "no mutation-based fuzzing engine is configured".
That absence is replaced by an executed campaign -- which found a real defect in
shipping code.

The defect: RedactionPolicy::apply PANICKED with "start byte index 2 is not a char
boundary; it is inside U+0307" on "U+0130 + api_key=secretvalue". The credential
search ran over input.to_lowercase() and then indexed the ORIGINAL string with the
offsets it found; lowercasing is not length-preserving (U+0130 is 2 bytes and
lowercases to 3, U+212A is 3 and lowercases to 1), so every offset after such a
character shifted and the following slice panicked -- in the CREDENTIAL-REDACTION
path, on a log line a Turkish keyboard produces routinely, so the incident
reporter could abort exactly when it was needed. The same pattern existed in
domain::scope::check_claim_text, where it was a silent mis-detection risk. Both now
search the original text with ASCII case folding and char-boundary checks, with
regression tests for the panic input and for the negative case that a key inside a
longer identifier is not a credential assignment.

The campaign: apps/desktop/src-tauri/tests/fuzz_campaign.rs -- deterministic and
dependency-free. Ten targets reachable from IPC with user-supplied text (the
truth-boundary guard, the credential redactor, the path and archive hardener, the
log redactor, the claim linter, the receipt importer, the package builder, the
ruleset authority, the chain-of-title date validator). A deterministic adversarial
phase of 4 634 inputs per target (every awkward character at every character
position of every seed: case-folding characters, combining marks, NUL, BOM,
separators, an emoji) followed by a seeded random phase of 20 000 mutation
iterations with deterministic shrinking of any reproducer. Label: ABBREVIATED --
no fuzzing scale is specified in the repository, so it does not claim DOD-038.

The campaign was itself mutation-tested, and BOTH of its early versions were
wrong: MUT-FUZZ-001 (reintroducing the lowercasing-offset bug) came back SURVIVED
twice -- first from corpus dilution (the pool hit its cap within a few hundred
iterations, leaving ~2% of picks on the seeds containing the key names), then
because the FIXTURE registered U+0130 as a registered secret, which apply()
replaces BEFORE the vulnerable pass runs, so the trigger character was scrubbed
from every input while a direct probe of the same code panicked. Only after both
fixes is MUT-FUZZ-001 CAUGHT, which is what makes the clean run's zero findings
meaningful. Thirteen controlled defects now run in scripts/mutation-proof.py.

GEN-027's applicability note now points at the executed campaign. DOD-038 stays
PARTIAL (its own rule forbids PASS for an abbreviated trial) but now records two of
its six named trial classes as executed: endurance (600 s soak) and fuzzing.

verification: verify.sh ok; DoD PASS 36, PARTIAL 3, FAIL 1, EXTERNAL_REQUIRED 2;
requirements 57/59 bound; coverage line 93.4% at the new epoch.
